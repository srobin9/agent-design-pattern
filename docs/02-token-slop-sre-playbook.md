# 토큰 70% 절감 & Anti-Slop SRE 운영 플레이북

왜 짧은 프롬프트 몇 문장으로 에이전트를 만들면 **코드는 지저분해지고(Slop) 토큰은 눈덩이처럼 불어날까요?**  
SRE의 장애 회고(Postmortem) 관점에서 근본 원인(Root Cause)을 분해하고, 이번 키트에 적용된 **4중 방어막**을 설명합니다.

---

## 1. Postmortem: 기존 방식에서 토큰이 폭발했던 3가지 구조적 원인

### 원인 ① 코딩 전 '레퍼런스 통째 로딩'으로 인한 기본 컨텍스트 오염
- LLM 과금은 **매 턴(Turn)마다 대화창에 쌓인 전체 히스토리 토큰을 다시 읽는 구조**입니다.
- 기존 ADK 기본 워크플로우는 초반에 샘플 레포지토리 여러 개를 메인 창에서 클론해 읽도록 유도합니다. 첫 줄 코드를 짜기도 전에 이미 **5만~12만 토큰**이 쌓이고, 이후 사소한 수정을 10번만 주고받아도 `10만 × 10턴 = 100만 토큰`이 증발합니다.

### 원인 ② 계약 없는 통짜 생성 (Big-Bang Generation = Slop)
- 아키텍처 경계(입출력 DTO, 상태 키, 제외 범위) 없이 *"장애 분석 에이전트 만들어줘"*라고 하면, AI는 불확실성을 메우기 위해 **쓰지도 않을 클래스, 과도한 예외 처리, 복잡한 인증 래퍼를 한꺼번에 10개 파일로 생성**합니다.
- 사람의 의도와 어긋난 코드가 이미 수백 줄 깔리면, 이를 고치느라 새로 짜는 것보다 3배 많은 토큰을 씁니다.

### 원인 ③ 장애 격리 실패 & 무한 재시도 루프 (Retry Storm)
- 에이전트 배선(ADK), 프롬프트, GCP IAM 권한, 외부 API 호출을 한 번에 섞어서 실행하면 에러가 났을 때 원인을 특정하지 못합니다.
- AI는 원인을 모른 채 *"이번엔 이렇게 바꿔볼게요"*라며 여러 파일을 동시에 건드리고(Shotgun Debugging), 고치면 옆이 깨지는 루프에 빠집니다.

## 2. 이 키트에 내장된 SRE 방식의 4중 방어막

| SRE 원칙 | 에이전트 개발 적용 장치 | 어디에 구현되어 있는가? | 토큰 절감 효과 |
| :--- | :--- | :--- | :--- |
| **1. Bulkhead (격벽 분리)** | 무거운 문서·샘플 코드 탐색과 긴 에러 로그 분석은 `research` 서브에이전트에만 시키고 메인 창에는 **25줄 요약본만 반입** | `lean-agent-architect` 스킬 + `GEMINI.md` | 메인 대화창 기본 두께 **70~80% 감소** |
| **2. Contract & Canary (카나리/스텁 검증)** | 스펙 승인 전 코딩 금지 + **Slice 1은 100% 로컬 Mock 도구로만 개통** 후 Slice 2에서 실서버/GCP 연결 | `.agents-cli-spec.md` + Thin Slice | 초기 갈아엎기(Rework) 및 권한 디버깅 혼선 **제로화** |
| **3. Circuit Breaker (서킷 브레이커)** | 동일 에러 **2회 연속 발생 시 코드 수정 즉시 중단** → 5줄 원인 분석표 보고 후 아키텍트 판단 대기 | `GEMINI.md` 4항 + 스킬 강제 규칙 | 디버깅 폭주(Retry Storm) 원천 차단 |
| **4. Stateless Worker (`STATE.md` 외부화)** | 진행 상태를 대화 기억에 의존하지 않고 디스크 파일(`STATE.md`)에 기록 → 슬라이스마다 `/compact` 또는 새 창 전환 가능 | `STATE.md` 자동 갱신 | 장기 프로젝트에서도 **첫 턴처럼 가벼운 컨텍스트 유지** |

## 3. 아키텍트·SRE를 위한 실전 운영 팁 3가지

### 팁 1: Python 코드를 직접 읽으려 하지 마시고 '경계(Boundary)'만 통제하세요
Java에서 외부 벤더 라이브러리를 쓸 때 내부 구현 코드를 다 읽지 않고 **Interface 시그니처, 타임아웃, 예외 계약, 테스트 통과 여부**만 보시는 것과 똑같습니다.
- **집중하실 곳**: `.agents-cli-spec.md`의 **1~4번(목적, 제외 범위, 입출력 항목, 금지 규칙)**
- **위임하실 곳**: ADK import 경로, 비동기 문법(`async/await`), Pydantic 문법 (AI + `pytest`가 검증)

### 팁 2: '새 대화창 전환'을 두려워하지 마세요
대화가 15~20턴을 넘어가면 이전의 불필요한 시행착오까지 매번 비용으로 청구됩니다.
- 슬라이스 하나가 끝났을 때 **왼쪽 사이드바에서 `New Conversation`을 누르고** 아래 한 줄만 쳐보세요:
  > `@STATE.md 와 @.agents-cli-spec.md 를 읽고 다음 슬라이스를 진행해줘.`
- 이전 대화의 군더더기 수만 토큰은 0이 되면서, 핵심 맥락은 100% 정확히 이어집니다.

### 팁 3: 작업 성격에 따라 모델을 스위치하세요 (FinOps)
Antigravity 설정에서 모델을 언제든 바꿀 수 있습니다 (대화 맥락은 그대로 유지됩니다).
- **설계 확정(Gate 1) & 서킷 브레이커 원인 분석**: **Pro / Carbon** (아키텍처 판단력이 중요할 때)
- **Slice 1 스텁 작성, 단위 테스트 추가, 단순 도구 연결**: **Flash** (스펙이 이미 확정되어 지시대로 구현만 할 때 — 속도는 빠르고 쿼터 소모는 대폭 절감)
