# Agent Spec (1-Page 아키텍처 계약서) — 완성 예시

> **예시 시나리오**: GCP Cloud Run 서비스 장애 발생 시 로그·메트릭·배포 이력을 병렬 수집해 초기 원인(Root Cause 후보)을 도출하는 **읽기 전용 SRE Triage 에이전트**

## 1. 해결할 문제 & 역할 경계 (Scope & Non-Goals)
- **핵심 목적 (한 줄)**: Cloud Run 서비스 알람 발생 시 에러 로그, 골든 시그널 메트릭, 최근 리비전 배포 이력을 대조해 유력 원인 가설 Top 2를 요약한다.
- **명확한 제외 범위 (Non-Goals)**:
  - 트래픽 전환, 리비전 롤백, 환경변수 수정 등 **상태 변경(Write/Mutate) 작업 일체 제외**
  - PagerDuty/Slack 웹훅 전송 및 프론트엔드 대시보드 구축 제외 (순수 에이전트 코어만 구축)

## 2. 입출력 계약 (Input / Output DTO)
- **입력 (Trigger / Input)**: `project_id: str`, `service_name: str`, `region: str`, `lookback_minutes: int = 30`
- **기대 출력 (Output 구조)**:
  1. `incident_summary`: 현상 2줄 요약 (발생 시각, 주 증상)
  2. `hypotheses`: 유력 원인 가설 최대 2개 (신뢰도 상/중/하 + 근거 로그/리비전 타임스탬프 명시)
  3. `verification_commands`: 온콜 엔지니어가 터미널에 바로 복사해 확인할 읽기 전용 `gcloud` 명령어 목록

## 3. 외부 연동 도구 & 데이터 소스 (Tools Required)
| 도구/기능명 | 역할 (읽기/쓰기 구분) | 연동 대상 (GCP/API/DB) | 인증 및 타임아웃 조건 |
| :--- | :--- | :--- | :--- |
| `fetch_error_logs` | 읽기 전용 (Read) | Cloud Logging API | ADC 기본 인증, 최대 50건 요약 반환, 타임아웃 10초 |
| `fetch_service_metrics` | 읽기 전용 (Read) | Cloud Monitoring API | 5xx 비율·p99 지연시간·인스턴스 수 시계열 요약, 타임아웃 10초 |
| `fetch_recent_revisions` | 읽기 전용 (Read) | Cloud Run Admin API v2 | 최근 5개 리비전 배포 시각·이미지 태그·변경 여부, 타임아웃 10초 |

## 4. SRE 가드레일 & 제약 조건 (Constraints & Safety Rules)
- **금지 동작 (Hard Block)**:
  - `lookback_minutes`가 `1 ~ 180` 범위를 벗어나면 Cloud Logging 스캔 비용 방지를 위해 **도구 실행 전 차단**
  - `project_id` 또는 `service_name`에 공백이나 셸 메타문자(`;`, `|`, `&`) 포함 시 즉시 차단
- **실패 처리 (Fallback)**:
  - 3개 API 중 일부가 권한 오류(`403`)나 타임아웃 발생 시 전체 실패시키지 않고, 해당 소스를 `"수집 불가(사유 명시)"`로 표기한 뒤 나머지 소스로 분석 계속 진행
- **성공 기준 (SLO / Success Criteria)**:
  - 정상 입력 시 3개 수집 도구 모두 호출 완료율 100%, 응답 내 근거 타임스탬프 누락 0건

## 5. ADK 아키텍처 패턴 매핑 (AI 자동 작성 → 아키텍트 승인 완료)
- **선택 패턴**: **`SequentialAgent` 내부에 `ParallelAgent`(Scatter-Gather) + 종합 분석 `Agent` 결합**
  - *선정 이유*: 로그·메트릭·배포 이력 3가지는 상호 의존성이 없는 Read 작업이므로 `ParallelAgent`로 동시 조회해 응답 지연을 1/3로 줄이고, 수집된 상태를 `triage_synthesizer`가 종합 분석함. (도구 호출과 `output_schema` 충돌 방지를 위해 수집기와 종합기를 분리)
- **상태(State) 흐름**:
  - `log_collector` → `output_key="error_logs"`
  - `metric_collector` → `output_key="service_metrics"`
  - `revision_collector` → `output_key="recent_revisions"`
  - `triage_synthesizer` → `{error_logs}`, `{service_metrics}`, `{recent_revisions}` 참조하여 최종 리포트 생성
- **가드레일 콜백**: `before_tool_callback=enforce_sre_read_guardrails` (파라미터 범위 `1 <= lookback_minutes <= 180` 및 문자열 검증을 파이썬 코드로 결정론적 강제)
- **Reference Samples (서브에이전트 격리 조회용)**: 별도 레시피 클론 불필요 (기본 ADK `ParallelAgent` + `SequentialAgent` 표준 패턴으로 충분)
